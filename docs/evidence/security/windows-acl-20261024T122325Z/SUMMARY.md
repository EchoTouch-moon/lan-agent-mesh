This host is the exact environment whose inherited ACLs triggered #41: zh-CN Windows 10.0.22621, user temp/profile inheriting `Everyone:Full` plus foreign ordinary-user SIDs. Full local `pnpm check` passed with 44 tests. See [run-metadata.json](run-metadata.json) for hashes.

- [Gate smoke](acl-gate-smoke.json), all three behaviours verified on the real host:
  1. **Deny case** — a directory additionally granting Everyone read: the non-Mock Gateway refused to start (`unsafe_directory`, exit 1), named the offending principals, and issued **no** `identity.key`/`gateway.lock`.
  2. **Mock continuation** — the same unsafe directory with `--mock`: started on loopback with a `[security]` stderr warning, served, and shut down cleanly (exit 0); no token on stdout.
  3. **Allow case** — a user-exclusive directory (`icacls /inheritance:r`, only Administrators + current user): the non-Mock Gateway started and shut down cleanly with no warning.
- The audit reads the real security descriptor as SID-based SDDL through **pure .NET calls** (`DirectoryInfo.GetAccessControl`): PowerShell cmdlets fail to load on hosts whose inherited `PSModulePath` targets PowerShell 7 (GitHub windows runners), and `icacls` name parsing breaks on console codepage/localization on zh-CN hosts — SIDs are unambiguous. Reparse points are rejected; allow-listed administrative principals are SYSTEM, `BUILTIN\Administrators` and the RID-500 local Administrator account. POSIX keeps mode/symlink checks, exercised on the macOS CI legs. Design, threat model and the minimal-vs-enhanced isolation boundary are in [ADR 0003](../../../adr/0003-windows-data-directory-isolation.md).
- The operator guide never modifies host ACLs and never elevates: the unsafe inherited policy of *this* host remains unchanged and is still an environment blocker for long-lived real credentials here until the operator creates a user-exclusive placement (guide in the ADR).

This delivers the G2 *minimal gate* implementation with real-host allow/deny evidence and cross-platform CI. It does not satisfy the physical Mac↔Windows W3 hardware gate (#15 remains pending) and does not by itself authorize real Harness or long-lived MCP credentials — that decision stays with the G2 review in #41.
