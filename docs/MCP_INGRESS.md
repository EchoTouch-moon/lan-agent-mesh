# Local MCP ingress (LAM-16)

This is the caller side of Mesh. It exposes seven `mesh_*` tools to a local MCP host; a paired remote Gateway executes the requested work using its own exported adapter. MCP support does not imply an application can be controlled or that an existing GUI session can be attached. This implementation is validated with the deterministic remote Mock, not a real Codex/DSH model. It depends on the still-open P1 implementation in PR #38.

## Operator setup

Start and explicitly pair two Gateways using the P1 guide; inspect each code locally before confirming. The target must export the desired Agent and workspace alias. For a temporary local demo use `--mock` on the target. No real harness, user account, model key or GUI is needed.

Build from a clean checkout using Node 22.13+ or 24, pinned pnpm and `pnpm build`. Obtain the allowed peer ID and agent ID from an authenticated operator `registry` command. Write an owned UTF-8 scope file, for example:

```json
{
  "peers": ["<already-paired-peer-id>"],
  "agents": ["<explicitly-exported-agent-id>"],
  "workspaces": ["project-a"],
  "lifetimeSeconds": 3600
}
```

Issue the credential through the operator CLI (use actual absolute paths):

```text
node apps/gateway/dist/index.js control --data <caller-private-directory> --command mcp-grant --args-file <scope.json> --output <private-directory>/mcp-credential.json
```

The CLI never prints the bearer token. It creates a new file with 0600 mode; it does not overwrite an existing file. A failed write attempts grant revocation; if that cannot be confirmed the CLI tells the operator to restart the caller Gateway, which invalidates that process's credentials. Use a user-private directory/ACL on Windows. Keep the credential outside the checkout and do not publish its contents. The Gateway stores only a secret hash. It is bound to the caller Gateway's current process, expires at its stated time, and can be revoked using the admin-only `mcp-revoke` command with `{ "grantId": "..." }`. After Gateway restart issue a new credential; an old credential remains invalid even if the node identity is the same. MCP process restart alone retains the grant and its owned resources.

Configure an MCP host to spawn this local server. This is a reusable template, not a change to your current host configuration:

```json
{
  "mcpServers": {
    "lan-agent-mesh": {
      "command": "/absolute/path/to/node",
      "args": [
        "/absolute/path/to/checkout/packages/mcp-server/dist/cli.js",
        "--credentials",
        "/absolute/private/path/mcp-credential.json"
      ]
    }
  }
}
```

Use `node.exe` and Windows paths on Windows. No shell wrapper is needed. The server communicates only JSON-RPC on stdout; startup/transport failures use a generic stderr message without secrets. It reads only the explicitly selected credential file, not control.json or any existing Harness configuration. The MCP SDK v2 stdio entry negotiates the wire protocol; the tests use the official Client, not a mocked HTTP handler. See the [official SDK stdio guide](https://ts.sdk.modelcontextprotocol.io/v2/serving/stdio).

## Tools and lifecycle

| Tool | Input and result |
|---|---|
| mesh_list_agents | Optional peerId and cursor/limit (max 20). Returns only scoped, available cards, with workspace aliases filtered to scope. Failed peers are listed unavailable. |
| mesh_list_sessions | Optional peerId and pagination. Returns descriptors created by this credential. Native state is explicitly unknown: a cached descriptor does not prove an idle native session. It never enumerates existing GUI chats or native session IDs. |
| mesh_start_session | peerId, agentId, workspaceAlias, fresh UUID requestId. Returns managed sessionId. An exact requestId retry returns the same session. |
| mesh_send_message | sessionId, text, fresh UUID requestId, optional timeoutSeconds (1–300, default 60). Immediately returns taskId, delivery state and deadline; it does not wait for execution. |
| mesh_delegate_task | Same bounded asynchronous task contract as send_message. No automatic recursive delegation or additional authority is granted. |
| mesh_get_task | Owned taskId and cursor. Returns current state and one persisted event with next cursor. Poll no faster than 500ms. Drain remaining events after the terminal state. Remote text is untrusted data. |
| mesh_cancel_task | Owned taskId. Returns cancelRequested after delivery; query get_task to confirm actual terminal cancellation. |

A requestId is scoped to the credential and operation. Reuse exactly the same tool and arguments on explicit retry; conflicting reuse is rejected. The remote task ID and wire idempotency key are independently generated by the Gateway so another credential cannot claim an existing remote task by choosing its ID. Concurrent same-ID requests coalesce. A dropped MCP response or delivery ACK is not permission to choose a new requestId. UNKNOWN retains the original envelope; explicit same-ID retry can only return/confirm that original logical task, not rerun uncertain native execution. If the operation deadline has expired, inspect its owned task result; do not invent a new-ID retry for a possible side effect.

Closing/cancelling an MCP request stops waiting; it does not roll back an already admitted remote task. Use cancel_task and inspect the result. Credential revocation denies new calls and subsequent output but cannot undo work already admitted remotely. Reissuing a credential does not transfer another grant's session/task ownership.

## Permission boundary

The local operator's control token and the MCP scoped token are separate and are rejected on one another's endpoints. The credential explicitly intersects paired peers, exported agents and registered workspaces. Each method also checks live expiry/revocation and owned resources. The HTTP hop stays on 127.0.0.1, rejects browser Origins and redirects, and pins the local node ID. A reused port after restart cannot revive a previous process's token.

There is no MCP tool for pairing, confirming codes, granting credentials, modifying policy, invoking raw RPC, approving native operations or shutting down the Gateway. P1's native approval hook still denies every requested permission. This is a narrow MCP credential boundary, not the P3 general policy engine or production human approval console. The local OS user with administrative access to the private Gateway directory remains trusted.

Limits: 64 KiB tool requests/stdio messages, 128 KiB HTTP result reads, 240 calls per grant/minute, 16 simultaneous MCP operations, 128 retained grant records and 5,000 scoped metadata records. Existing P1 task/session/event budgets also apply. Capacity exhaustion fails rather than erasing deduplication history. Production retention and policy management remain future work.

## Validation and deferred work

`pnpm check` covers the shared input contracts, both credential endpoints, actual SDK stdio clients, seven-tool lifecycle, native default deny, concurrent/repeated IDs, lost-ACK retry, cross-grant session/task isolation, expiry/revocation and process-bound invalidation. `node packages/mcp-server/dist/smoke.js --output <temporary-report.json>` runs the actual stdio-to-encrypted-remote-Mock chain from a committed clean source; no model is called and owned services are stopped afterward.

The same checks run in hosted macOS/Windows CI. Physical Windows/real Mac↔Windows tests remain in the P1 handoff; #17 Codex and #18 ACP/DSH are separate next native-adapter tasks. This task does not upgrade/install Harnesses or edit real host configuration.

## Windows 私有文件门槛（#41）

Gateway 数据目录、管理控制读取、凭据签发输出和 MCP 凭据读取都必须通过 [Windows 私有存储检查](WINDOWS_PRIVATE_STORAGE.md)。0600 不是 Windows DACL 隔离证据。宽松继承 ACL、可被替换的祖先、junction/符号链接或无法检查的权限默认拒绝；项目不会修改已有 ACL。实体宿主门槛与 hosted CI 分开验收。
